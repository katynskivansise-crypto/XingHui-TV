## 关键结论
1. **规则/数据层（引擎）已对齐原版主流能力**，且 drpy 生态可继续跟进——重构的技术地基成立。
2. **真正的分水岭是 P3（安卓替换验证）**：现在还没有一枚真实 APK，播放内核（ExoPlayer）也没在真机跑通。这一步不完成，"对比原版"只能是纸面对比。
3. **P5 播放增强与 P6 设置/持久化**是后续工作量主体（相当于把整个 App 产品层重写）。
4. 下一步优先级：**上传仓库触发 CI 出 APK → 壳内接播放内核（ExoPlayer/mpv）验证播放 → 补收藏/历史/设置**。

## 播放内核选型：ijk / ExoPlayer / mpv 三选并存【2026-10-28 补充】

用户需求：除 ijk/ExoPlayer 外，**再引入 mpv** 作为播放内核。

- **可行性**：安卓端用 mpv-android（官方维护）的 `libmpv` 核心，JNI 封装接入，与 ijk/ExoPlayer 并存。
- **分工建议**：
  - `mpv`：解码强、字幕/音轨/滤镜/色彩、本地与复杂流 → 高兼容播放、外挂字幕、DIY 滤镜
  - `ExoPlayer`：DASH/HLS/流媒体、自适应码率 → 主流网络点播
  - `ijk`：老协议/TS 流/自定义源 → 原版 TVBox 老源
- **接入架构（安卓壳）**：定义 `PlayerKernel` 抽象接口（open/play/pause/seek/回调），播放时按所选内核路由；mpv 用预编译 libmpv so（arm64-v8a/armeabi-v7a/x86_64，含 ffmpeg，每架构约 10–20MB）+ JNI 封装，自绘 Surface；UI 加"播放内核"设置项。
- **成本**：APK 体积明显增大（mpv+ffmpeg so）、维护三套播放器与事件桥接；mpv 不适配 DRM/部分流媒体协议（仍走 ExoPlayer）。
- **状态**：规划已记录；实现依赖 P3 安卓环境（沙盒无 Android SDK，先上传 GitHub 验证首枚 APK）。
